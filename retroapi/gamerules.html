Game rules & modes

The modern rules that have a beta equivalent, the four game modes, and two rules beta could never have had.

Game rules

Beta has none: whether fire spreads, whether mobs spawn and whether the sun moves are all hard-coded. RetroAPI backports the rules that map cleanly onto beta's own code, under modern's names, with /gamerule to read and set them.

RuleDefaultWhat it changes
doFireTicktruefire neither spreads nor burns out
doMobSpawningtruethe natural spawner does nothing
doMobLoottruedying mobs drop nothing (players are keepInventory's business)
doTileDropstruebroken blocks yield nothing
keepInventoryfalsedying scatters nothing
mobGriefingtruecreepers and ghasts still explode and hurt, but leave terrain alone
doDaylightCycletruethe sun stops moving; /time set still works
doWeatherCycletrueweather stops changing on its own; /weather still works
randomTickSpeed3scaled onto beta's own rate, so 3 means "exactly as beta always was"
doImmediateRespawnfalseno death screen
commandBlockOutputtruecommand block output reaches the log
sendCommandFeedbacktrueand seeds a new command block's "track output"
maxCommandChainLength65536how far one chain may walk in a tick
maxBlockModifications32768the most blocks one /fill may touch
sprintingfalsesprinting, which arrived in 1.8
swimmingfalseswimming as a pose and a movement mode

Sprinting and swimming are off by default because a beta world should still feel like beta unless somebody asks otherwise. They are independent: with sprinting on and swimming off, entering water simply stops the sprint, which is what modern does too.

Your own rules

public static final RetroGameRule MY_RULE =
	RetroGameRules.registerBoolean("mymod:doSomething", true);

// anywhere afterwards:
if (RetroGameRules.getBoolean(MY_RULE)) { /* ... */ }

Register during init, before any world loads, so the rule exists by the time /gamerule lists it and a saved value is read back. registerInt is the other half. Namespace your key; the vanilla-equivalent rules deliberately are not namespaced, because they are the vanilla names.

Values live with the world, in the sidecar. The server owns them and sends the whole set to every client on join and again whenever one changes, because some rules are decided client-side before the server ever sees the move.

Game modes

All four, under modern's names and ids, set with /gamemode <mode> [targets].

ModeWhat it does
survivalbeta, unchanged
creativeno damage, no health bar, instant breaking with no drops, flight, the creative inventory
adventuremay not break or place blocks
spectatorflies through terrain, invisible to other players, may not interact

A player's mode is permanent player data: it survives death, dimension changes and reconnects, exactly as on modern.

if (RetroGameModes.get(player) == RetroGameMode.CREATIVE) { /* ... */ }

RetroGameModes.set(player.name, RetroGameMode.SPECTATOR);

Flight

Creative flight is modern's: double-tap jump to start, space and shift for up and down, momentum and air friction rather than a constant glide, doubled speed while sprinting, and touching the ground turns it off. Spectator always flies and passes through terrain.

The scroll wheel is a throttle in spectator and under /noclip, as it is in modern's spectator; in creative the wheel stays on the hotbar where it belongs.
