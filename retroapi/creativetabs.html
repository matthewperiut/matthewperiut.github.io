Creative tabs

Item groups, built the way Fabric API builds them, in a creative inventory backported from modern.

Beta has no creative mode, so RetroAPI brings one: /gamemode creative, and a creative inventory ported from modern Minecraft's, down to the panel, the tab strip, the scrollbar and the search box. Tabs are registered content like anything else, and a mod adds one the way it would on modern with Fabric API.

Creative is deliberately hidden. There is no button and no world-creation switch, exactly as modern hides command blocks: the only way in is /gamemode. See Game rules & modes.

Your own tab

Build it during your mod's initialisation. build() registers it, so there is no second call to remember.

src/main/java/com/example/example_mod/ExampleMod.java, in initRetro()
public static RetroItemGroup GEMS;

// ... in initRetro(), after the items exist:
GEMS = RetroItemGroup.builder(id("gems"))
	.displayName(Text.literal("Gems"))
	.icon(() -> new ItemStack(GEM))
	.entries(entries -> {
		entries.add(GEM);
		entries.add(GEM_BLOCK);
		entries.add(GEM_PICKAXE);
	})
	.build();
Builder methodWhat it does
displayName(Text) / displayName(String)the name on the tab's tooltip and above the grid
icon(Supplier<ItemStack>)the item drawn on the tab itself; a supplier, so it may depend on things registered later
entries(collector)what the tab contains, in order
build()builds and registers

entries runs every time the screen opens, not once at registration. A tab can therefore show something that depends on the world, or on what another mod added after you.

Filling a tab

The collector handed to entries takes blocks, items and stacks, and knows about beta's metadata subtypes.

CallAdds
add(Item) / add(Block)one entry, subtype 0
add(Item, int) / add(Block, int)a specific subtype: a wool colour, a log species
add(ItemStack)a stack you built yourself, components and all
addRange(Block, int, int)every subtype in a range, which is how wool and dye are listed
.entries(entries -> {
	entries.add(GEM);
	entries.addRange(Block.WOOL, 0, 15);   // all sixteen colours
	entries.add(new ItemStack(GEM_SWORD.id, 1, 0));
})

Adding to somebody else's tab

The equivalent of Fabric's ItemGroupEvents.modifyEntriesEvent. Works on the vanilla tabs and on other mods' tabs alike.

RetroItemGroups.modifyEntries(VanillaItemGroups.INGREDIENTS, entries -> entries.add(GEM));
RetroItemGroups.modifyEntries(VanillaItemGroups.BUILDING_BLOCKS, entries -> entries.add(GEM_BLOCK));

The tabs that already exist

RetroAPI sorts beta's own content into modern's tabs, in modern's order. Where modern has something beta does not, the entry is simply missing rather than replaced.

Field on VanillaItemGroupsTab

COLORED_BLOCKSColored Blocks, the sixteen wools

OPERATOROperator Utilities: command blocks, spawner, bedrock
SEARCHSearch: everything registered, yours included, with the search field

The search tab builds itself from the registries, so anything you register appears there without you doing anything. It is also the quickest way to check a new item registered at all.

Pages

Ten tabs fit on a page. Register more and the screen grows the same page arrows Fabric API adds on modern, in the same place, with Page Up and Page Down as shortcuts. The search tab is pinned to every page.

What a click does

Clicking an item asks the server for that stack; the server checks the asker really is in creative before handing anything over. In singleplayer there is nobody to ask, so it goes straight into the inventory. This is the one place the port differs in shape from modern, which moves the stack through a container beta does not have.
